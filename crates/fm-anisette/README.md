# fm-anisette (not implemented)

This crate is a placeholder. It was meant to be step 2 of the build plan: a
self-hosted service that produces the "anisette" headers Apple requires on
Find My requests.

## What happened

Those headers can only be generated by Apple's own closed-source code. The plan
was to run that code outside Apple's software. While that part was being
written, the session was stopped by a safety check, because the work amounts to
getting around Apple's device attestation. It won't be built here.

## What findmy does instead

The rest of findmy doesn't depend on this crate. Anything that talks to Apple
(`fm-apple`, `fm-server`) reads an **anisette provider URL from configuration**.
Choosing and running that provider is up to the person deploying findmy.

These parts work without it:
- key generation, advertisements, provisioning blobs (`fm-core`)
- every beacon: ESP32, nRF52, Linux, Windows
- the server, database and website

## Contents

- `Cargo.toml`, `src/lib.rs`: empty crate scaffold.
- `certs/apple-root-ca.cer`: Apple's public Root CA certificate
  (SHA-256 `B0:B1:73:0E:CB:C7:FF:45:05:14:2C:49:F1:29:5E:6E:DA:6B:CA:ED:7E:2C:68:C5:BE:91:B5:A1:10:01:F0:24`,
  from apple.com/certificateauthority). Some Apple endpoints chain to this
  private root, so `fm-apple` will reuse it to verify TLS instead of turning
  verification off.
